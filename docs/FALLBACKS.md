# Extraction and fallback order

All three paths are available in the standard pipeline. Each trigger stops after the first path returns valid target text, and no provider request is made when the normalized target is empty.

| Trigger | Order | Context behavior |
| --- | --- | --- |
| Selection | UI Automation -> native Edit/RichEdit -> clipboard Copy -> OCR | UI Automation requests the containing sentence/range when available. The trigger captures the source process and `GA_ROOT` top-level window; UIA descendants may use a different renderer PID only when they remain inside that captured root tree. The bounded native-control fallback derives sentence context without touching the clipboard. For a drag or double-click selection only, clipboard Copy then uses the same bounded snapshot/restore mechanism as Manual; a plain click never invokes Copy. Copy is sent only while the captured source root remains foreground. Clipboard text alone has no extra context. OCR uses the selected rectangle and recognizes the surrounding text. |
| Manual | UI Automation -> clipboard Copy -> OCR | UI Automation is preferred. Manual captures the foreground `GA_ROOT` window when its hotkey fires. Clipboard fallback snapshots supported HGLOBAL-backed formats into bounded independent memory, verifies that root is still foreground, copies the current selection on a dedicated OLE thread, and restores the snapshot through a short-lived clipboard owner. Snapshotting and application Copy response have separate deadlines. A no-change result may be retried once only if the foreground root and original clipboard sequence/owner remain unchanged. Clipboard text alone has no extra context. Unsupported or over-budget formats fail closed. |
| Hover | UI Automation -> OCR | UI Automation resolves the word at the pointer and derives its containing sentence. Starting at the pointed element, it searches a bounded nearest-ancestor chain for the first `TextPattern` provider, revalidates the native `GA_ROOT` under the unchanged pointer before accepting the range, and never accepts content outside the captured root/process boundary. OCR uses a bounded DPI-aware 1536×384 logical-pixel context crop and accepts only a word box containing the pointer; blank space does not snap to a nearby word. If UI Automation finds a valid word but no containing sentence, one bounded OCR pass may attach only a sentence containing that unchanged word. It may never replace the UIA target, and Hover fails locally when no containing sentence is available. |

OCR screenshots exist only as in-memory pixel buffers for the duration of recognition. They are not written to disk. OCR availability depends on Windows OCR language/runtime support; failure is silent for automatic triggers.

The target is normalized before admission. Whitespace-only and zero-width-only text is treated as absent. A word target is sent with its locally derived sentence context whenever the extraction path can provide it. Clipboard fallback may provide only the selected target when the source application exposes no usable context API.

The ordinary-application support target covers native controls, browsers, Electron applications, Office, terminals, and PDF readers. Universal extraction is not possible where Windows or the source deliberately blocks access, including password fields, protected/DRM surfaces, higher-integrity processes, secure desktops, or surfaces exposing neither selectable text nor capturable pixels. Those cases fail without a provider request.
